# 代码说明

本文档面向后续维护者和 Codex，说明妙响自动化控制台的模块职责、主要数据流、失败恢复方式和扩展入口。

## 1. 总体结构

程序由三个层次组成：

1. 浏览器界面：`frontend/` 下的单页控制台。
2. HTTP 与 WebSocket 接口：`backend/api.py`、`backend/main.py`、`backend/events.py`。
3. 自动化任务层：`backend/task_engine.py`、`backend/page_flow.py`、`backend/pipeline.py`、`backend/pipeline_queue.py`。

持久化使用 `backend/storage.py` 中的 JSON 仓库，数据模型统一放在 `backend/models.py`。

## 2. 启动入口

### `backend/main.py`

- 解析 `--host`、`--port` 和 `--no-open`。
- 调用 `create_app()` 创建 FastAPI 应用。
- 默认打开 `http://127.0.0.1:8787`。
- 开发和打包环境都使用同一个入口。

### `backend/config.py`

- 计算源码运行和 PyInstaller 运行时的目录。
- 源码模式：项目根目录来自 `backend/config.py` 的上级目录。
- 打包模式：可写数据位于 exe 同级目录，前端资源从 PyInstaller `_MEIPASS` 读取。
- 负责创建 `data/`、`logs/`、`screenshots/`。

## 3. API 层

### `backend/api.py`

`create_app()` 是应用装配中心，主要职责包括：

- 创建账号、设置、模板、任务状态和流水线仓库。
- 创建事件总线、浏览器管理器和任务引擎。
- 把前端静态资源挂载到 `/assets`。
- 注册 REST API、WebSocket 和全局异常处理。

接口按功能分为以下组：

| 接口组 | 作用 |
| --- | --- |
| `/api/accounts` | 账号增删改查、复制和目录选择 |
| `/api/accounts/{id}/songs` | 读取并解析当天歌词 |
| `/api/accounts/{id}/lyric/templates` | 作词模板管理 |
| `/api/accounts/{id}/lyrics/generate*` | AI 作词和流式进度 |
| `/api/accounts/{id}/uploads` | 当天上传批次和重置 |
| `/api/uploads/runs*` | 上传、停止、验证码和重传 |
| `/api/runs*` | 生成音乐任务及暂停、继续、停止 |
| `/api/pipeline/runs*` | 单账号完整流水线 |
| `/api/pipeline/queue/runs*` | 多账号串联队列 |
| `/api/settings*` | 运行参数和 AI API 配置 |
| `/ws` | 日志、任务和流水线实时事件 |

业务异常统一映射为 JSON 错误。页面流程异常会携带截图路径，前端在日志面板中显示。

## 4. 数据模型

### `backend/models.py`

核心模型：

- `AccountConfig`：账号、路径、Chrome 端口、模型、人声、批次和上传信息。
- `ConsoleSettings`：超时、日志上限和 AI API 配置。
- `LyricData`：歌名、歌词和曲风。
- `LyricTemplateConfig`：模板绑定账号、风格、格调、多选主题和生成数量。
- `SongProgress`、`TaskSnapshot`：单首歌曲和生成任务状态。
- `PipelineSongState`、`PipelineSnapshot`：单账号完整流水线状态。
- `PipelineQueueItem`、`PipelineQueueSnapshot`：多账号队列状态。

模型中的默认值和字段范围是 API 校验的第一道边界。新增任务参数时，应先在模型中定义，再向 API 和前端传递。

## 5. 持久化

### `backend/storage.py`

`JsonStore` 使用“临时文件 + `os.fsync` + `Path.replace`”进行原子写入。读取损坏 JSON 时会把原文件改名为 `.corrupt.json`，然后恢复默认值。

仓库职责：

- `AccountRepository`：账号配置。
- `RunStateRepository`：按日期、账号、歌词文件记录生成结果。
- `PipelineStateRepository`：单账号流水线快照。
- `PipelineQueueStateRepository`：多账号队列快照。
- `LyricTemplateRepository`：账号专属作词模板。

主要数据文件：

```text
data/accounts.json
data/settings.json
data/run_state.json
data/lyric_templates.json
data/pipeline_state.json
data/pipeline_queue_state.json
```

## 6. 歌词读取与 AI 作词

### `backend/lyrics.py`

- 解析 Markdown 歌词文件。
- 提取歌名、歌词和歌曲风格。
- 校验歌词和曲风最小长度。
- 枚举指定日期目录下的歌词文件。

### `backend/ai_lyrics.py`

主要流程：

1. `build_lyric_payload()` 合并通用系统提示词和模板参数。
2. 模板与通用规则冲突时，明确告诉 AI 以模板内容为准。
3. 输出统一约束为：

```json
{"songs":[{"song_name":"...","lyrics":"...","style":"..."}]}
```

4. `parse_lyric_response()` 校验数量、字段、长度和重复歌名。
5. `stream_generate_lyrics()` 解析 OpenAI 兼容流式响应，并向前端推送连接、推理摘要、字符数和歌名。
6. `render_lyric_markdown()` 把结果转换为控制台歌词格式。

修改输出格式时，应同时更新：

- 通用提示词中的 JSON 约束。
- `parse_lyric_response()`。
- `render_lyric_markdown()`。
- `tests/test_ai_lyrics.py`。
- `tests/test_api.py` 中保存歌词的接口测试。

## 7. Chrome 管理

### `backend/browser.py`

- 查找本机 Chrome 或 Edge。
- 校验 Chrome 用户目录。
- 构造带远程调试端口的 Chrome 命令。
- `ChromeSession` 等待 CDP 可用并维护浏览器进程。
- `BrowserManager` 保证同一时间只有一个账号浏览器操作，并支持关闭、当前状态查询和任务后清理。

账号复制时不会复用同一个浏览器进程。复制逻辑会复制 Chrome 用户目录，并为新账号分配新的调试端口。

## 8. 页面流程

### `backend/page_flow.py`

该模块集中封装页面选择器、输入方式和等待条件。

#### 通用交互

- `trusted_click()`、`dom_click()`：兼容普通点击和页面拦截。
- `paste_text()`、`type_segmented()`：优先尝试粘贴，失败时回退分段输入。
- `clear_and_type()`：清空输入框并填写内容。

#### 生成流程

- `ensure_create_page_ready()`：确认创作页登录和可用状态。
- `select_model()`、`select_singer()`：选择模型和 Sway 人声。
- `fill_inputs()`：输入歌词与曲风。
- `generate()`、`wait_for_generation()`：提交并等待平台返回。
- `classify_generated_cards()`：按歌名和歌词匹配生成结果。
- `export_candidate()`、`download_song()`：导出和下载。
- `export_alternate_version()`：导出未使用的第二版本，用于不及格歌曲替换。

#### 上传流程

- `upload_album()`：批量上传歌曲和填写专辑信息。
- `_remove_noncompliant_upload_songs()`：在当前上传页面移除不合格曲目。
- `_configure_upload_ai_tools()`：设置“以下歌曲均使用 AI 创作”等选项。
- `_fill_authorization()`：填写账号中的授权真实姓名。
- `_wait_for_external_verification()`：等待用户输入手机验证码。
- `_wait_publish_completion()`：等待“已完成作品上传，审核中”页面。

页面改版时优先只修改此模块，不要在上层任务引擎中散落新的 CSS 选择器或等待逻辑。

### 下载安全

`archive_download()` 会先下载到临时文件，确认文件有效后再替换目标。生成失败或下载失败时保留旧文件。

## 9. 生成任务

### `backend/task_engine.py`

`TaskEngine` 同时管理生成任务和上传任务，但两者互斥。

生成任务入口：

- `start()`：创建生成快照并启动异步任务。
- `pause()`、`resume()`、`stop()`：控制任务状态。
- `_process_batch_with_retries()`：处理批量生成。
- `_process_with_retries()`：处理单首歌曲，包含模型选择、匹配、导出、下载和重试。
- `_finish_song()`：更新断点和任务统计。

上传任务入口：

- `start_upload()`：普通上传。
- `start_regeneration_upload()`：重新生成待发布歌曲后上传。
- `submit_upload_code()`：提交用户输入的验证码。
- `stop_upload()`：停止上传并释放浏览器。
- `_run_upload()`：普通上传主流程。
- `_run_regeneration_upload()`：重新生成与替换主流程。

新增任务步骤时，应同时考虑暂停点、停止点、快照更新和事件推送，不能只实现正常路径。

## 10. 完整流水线

### `backend/pipeline.py`

单账号流水线 `PipelineEngine` 的阶段：

1. `lyrics`：按模板调用 AI 作词并保存到账号歌词目录。
2. `generation`：复用生成任务逻辑生成和下载。
3. `pre_upload`：根据配置决定是否暂停确认。
4. `upload`：复用上传任务逻辑发布。
5. `report`：汇总状态。

`start()` 仍用于单账号完整流水线。`start_from()` 和 `stop_after_stage` 供多账号队列复用某个账号的阶段快照。

### `backend/pipeline_queue.py`

`PipelineQueueEngine` 按全局阶段执行多个账号：

- 第一轮按账号顺序完成所有 AI 作词。
- 第二轮按账号顺序完成所有生成、导出和下载。
- 第三轮按账号顺序完成所有上传发布。
- `phase` 表示当前全局阶段：`lyrics`、`generation`、`upload` 或 `report`。
- 每个队列项包含 `account_id`、`template_id` 和自己的 `PipelineSnapshot`。
- 支持队列整体停止。
- 生成阶段统一使用 `PipelineSnapshot.generation_max_retries`，当前固定为 2。
- 前端通过 `pipeline_snapshot` 查看每个账号自己的歌曲明细。

## 11. 前端

### `frontend/app.js`

前端使用一个 `state` 对象维护页面状态，包括账号、歌词、生成任务、上传任务、流水线和实时日志。

关键机制：

- `api()` 封装同源 REST 请求和错误处理。
- `/ws` 接收 `task_status`、`upload_status`、`pipeline_status`、`pipeline_queue_status` 和日志事件。
- `localStorage` 保存生成模型和 Sway 人声，刷新后不会恢复默认值。
- `render*()` 函数按快照重新绘制列表和按钮状态。
- 日期目录由前端显示，后端按当天日期读写。

前端没有构建工具，修改 `app.js`、`index.html` 或 `styles.css` 后刷新浏览器即可生效。生产打包前应更新静态资源查询版本，避免浏览器缓存旧文件。

## 13. 打包

`打包EXE.bat` 使用 PyInstaller `--onedir`：

- 入口：`backend/main.py`
- 前端资源：`frontend/`
- 收集 Playwright、Uvicorn、FastAPI、Pydantic、HTTPX 和证书资源
- 输出：`dist/MiaoxiangConsole/`

运行时目录规则由 `backend/config.py` 统一处理。不要直接在业务模块中使用 `__file__` 构造数据目录，否则打包后会写到只读或错误位置。

## 14. 扩展建议

增加新的浏览器平台时，建议按以下边界实施：

1. 在 `models.py` 增加平台和账号字段。
2. 在 `browser.py` 增加浏览器配置。
3. 新建独立 `*_page_flow.py`，避免把选择器混入通用 `page_flow.py`。
4. 在任务引擎中按平台分派流程。
5. 为 REST、状态恢复和失败页面增加测试。

修改模型选择、Sway 人声或上传规则时，必须同时检查：

- `AccountConfig` 和请求模型。
- `/api/runs` 与上传启动接口。
- `TaskEngine` 参数传递。
- `PageFlow` 页面操作。
- 前端控件状态和 `localStorage`。
- API、页面流程和任务引擎测试。

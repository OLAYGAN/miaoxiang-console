# 妙响音乐自动化控制台 v2 设计文档

## 1. 目标

构建一个运行在本机的网页控制台，用于稳定执行妙响平台的音乐生成、导出和下载流程。用户可以在界面中管理账号、选择歌词、调整运行参数，并一键启动自动化任务。

本版本的核心目标是稳定和可控：

- 运行时零 AI 参与，全部动作由确定性脚本执行。
- 单账号串行处理，不支持并行任务。
- 支持多个账号配置，但每次只允许一个任务运行。
- 每一步都有硬超时、日志、状态记录和异常截图。
- 支持失败重试、断点续跑、用户停止和资源清理。
- 支持完整闭环：歌词解析、页面设置、生成、进入编辑器、导出、下载、归档和状态记录。

## 2. 非目标

- 不做平台检测规避、验证码绕过、指纹伪装或随机人类轨迹模拟。
- 不承诺规避平台封禁；账号风险由平台规则决定。
- 第一版不做拖拽式流程编排。
- 第一版不支持多账号并行。
- 第一版不在界面内编辑 Python 源码。

## 3. 技术架构

```text
本地浏览器控制台
  http://127.0.0.1:<port>
        |
        | 配置、启动、暂停、继续、停止
        v
FastAPI 后端
  - 账号管理
  - 配置管理
  - 任务队列
  - 实时日志
  - 截图和状态记录
        |
        v
任务执行器
  - 单账号串行
  - 单首歌有限状态机
  - 固定超时
  - 重试和断点记录
        |
        v
Python Playwright
  - 启动标准 Chrome 持久用户目录
  - 浏览器级真实输入事件
  - 必要时对不可视口元素使用 DOM click
        |
        v
妙响平台
```

### 3.1 后端

- Web 框架：FastAPI。
- 自动化：Python Playwright。
- 浏览器：标准 Chrome，使用每个账号独立的持久化用户数据目录。
- 实时通信：WebSocket 推送任务状态和日志。
- 配置和状态：优先使用 JSON 文件，保持易于备份、迁移和人工检查。

### 3.2 前端

- 本地网页控制台，采用轻量前端结构。
- 不依赖互联网服务，所有数据保存在本机。
- 通过轮询或 WebSocket 展示任务进度，避免界面假死。

## 4. 账号模型

每个账号保存以下配置：

| 字段 | 说明 |
|---|---|
| account_name | 账号显示名称 |
| chrome_profile_dir | 独立 Chrome 用户数据目录 |
| chrome_debug_port | 独立调试端口 |
| lyric_dir | 歌词根目录 |
| output_dir | 成品根目录 |
| download_dir | 浏览器下载目录 |
| model_name | 目标模型，默认 `Sway v5.5` |
| singer_name | 虚拟歌手，默认 `老岩` |
| max_retries | 单首歌最大重试次数，默认 3 |
| generation_batch_size | 一次连续提交的歌词数量，默认 2，最大 2 |
| song_interval_seconds | 每首歌之间的间隔 |

账号配置支持新增、编辑、删除和复制。删除账号只删除控制台配置，不自动删除 Chrome 用户数据目录和已下载音乐。

同一时间最多一个任务运行。任务运行中禁止修改当前账号的关键路径、端口和模型配置。

## 5. 控制台界面

### 5.1 账号区

- 选择当前账号。
- 管理账号配置。
- 显示当前任务运行状态。

### 5.2 任务区

- 自动列出当天当前账号下的歌词 `.md` 文件。
- 支持全选、反选、只选失败项。
- 一键开始处理。
- 支持暂停、继续、停止。
- 每首歌显示状态：待处理、解析失败、生成中、导出中、下载中、成功、失败、已达上限。

### 5.3 日志区

- 实时滚动展示日志。
- 每条日志包含时间、步骤、歌曲名、级别和详情。
- 异常日志展示截图路径。
- 支持复制日志、打开日志文件、打开截图目录。

### 5.4 配置区

基础配置：

- 模型名称。
- 虚拟歌手。
- 最大重试次数。
- 每首歌间隔。

等待配置：

- 页面加载等待。
- 生成最大等待，默认 300 秒。
- 编辑器导入等待，默认 8 秒。
- 导出跳转最大等待，默认 60 秒。
- 下载等待，默认 30 秒。

高级配置：

- 创作页 URL。
- 资产页 URL。
- 编辑器 URL 关键字。
- CDP 地址。
- 调试截图目录。

配置按账号保存，修改后自动保留上一版备份。

## 6. 歌词解析

歌词文件为 Markdown 文本，包含三个部分：

1. 歌名：匹配 `歌名：《歌曲名》` 或 `歌名: 歌曲名`。
2. 歌词：提取 `## 歌词` 到 `## 歌曲风格` 之间的内容，并移除第一行歌名。
3. 风格：提取 `## 歌曲风格` 之后的内容。

解析成功条件：

- 歌名非空。
- 歌词非空且长度大于 100。
- 风格非空且长度大于 50。

解析失败的歌曲不进入浏览器流程，直接标记失败并处理下一首。

## 7. 自动化流程

每首歌执行以下状态机：

```text
读取歌词
  ↓
打开创作页并确保页面就绪
  ↓
填入歌词并验证
  ↓
填入风格并验证
  ↓
记录生成前资产列表第一首歌
  ↓
点击生成
  ↓
检测生成上限
  ↓
等待生成完成
  ↓
进入编辑器
  ↓
导出歌曲
  ↓
下载歌曲
  ↓
移动并重命名成品
  ↓
记录成功
```

### 7.0 批量生成模式

两首不同歌词会连续提交，等待平台返回 0 到 4 张新生成卡片。脚本逐张打开详情，读取「歌词」内容并与提交歌词归一化比对。每个歌词选择资产列表中最新的第一个匹配版本导出；其余版本仅用于校验。生成缺失的歌词单独重试，导出失败不触发重新生成。

### 7.1 页面初始化

- 使用专业模式，以 `.ql-editor` 作为就绪标志。
- 模型选择默认 `Sway v5.5`。
- 关闭模型下拉中的“自动”开关时，必须点击开关元素本身，不能点击“自动”文本。
- 列表底部模型可能不可见，允许对具体选项使用 DOM click。
- 虚拟歌手开关必须点击 `.semi-switch` 元素，并通过 `aria-checked` 或选中类名验证。
- 页面已就绪时只做校验，不重复设置。

### 7.2 点击策略

默认使用 Playwright 鼠标 API：

1. 通过文本、CSS、属性或容器关系定位元素。
2. 获取元素边界并计算中心点。
3. 移动鼠标。
4. 短暂悬停。
5. 点击。

这是浏览器级 trusted input event，不抢占 Windows 真实鼠标。

以下场景可使用 DOM click：

- 下拉列表底部不可视口选项。
- 明确记录为真实鼠标点击无效的特殊元素。

每次 DOM click 都写入日志，便于排查。

### 7.3 长文本输入

- 歌词输入框：`.ql-editor`。
- 点击输入框，等待焦点。
- 全选并删除旧内容。
- 按每段 50 字输入，段间延迟 10 毫秒。
- 输入后读取内容并验证长度。

风格输入框使用 textarea 定位，清空后输入并验证长度。

### 7.4 生成完成检测

- 生成前记录资产列表第一首歌名。
- 点击生成后按固定间隔检测第一首歌名。
- 第一首歌名从空变为有值，或从旧值变为新值，即认为生成完成。
- 不使用“存在播放按钮”“存在老岩歌曲”或固定等待作为完成依据。
- 超时后保存截图并进入重试。

### 7.5 导出与下载

- hover 最新歌曲卡片，点击“编辑”，再点击“编辑器”。
- 等待编辑器 URL 和音轨导入。
- 点击顶部“导出”。
- 在弹窗中用键盘方式修改歌曲名，不直接设置 React 受控 value。
- 点击弹窗底部导出按钮。
- 等待资产页。
- 切换到“生成结果”标签。
- 通过目标歌曲卡片内的 `trigger` 元素打开更多菜单。
- 使用 Playwright download event 捕获下载，不用 HTTP 客户端直接请求音乐 URL。
- 下载完成后移动到 `output_dir/日期/歌曲名.mp3`。
- 验证目标文件存在且大小大于 0。

## 8. 任务控制

### 8.1 暂停与继续

- 暂停只在步骤边界生效，避免中途破坏页面状态。
- 当前原子步骤完成后，任务进入暂停状态。
- 继续时先校验浏览器和页面仍然可用，再执行下一状态。

### 8.2 停止

- 停止请求始终有效。
- 后台收到请求后，不再开始新步骤。
- 当前操作给予短暂收尾时间。
- 保存任务状态、日志和必要截图。
- 统一释放 Playwright 和 Chrome 资源。

### 8.3 重试

- 每首歌最多重试 `max_retries` 次。
- 每次失败后等待 5 秒。
- 重试从填入歌词开始。
- 生成上限不重试。

## 9. 异常处理

| 异常类型 | 处理 |
|---|---|
| 生成上限 | 截图，记录状态，停止全部任务 |
| 歌词解析失败 | 标记失败，继续下一首 |
| 页面未就绪 | 截图，尝试恢复一次，失败后停止任务 |
| 生成超时 | 截图，进入重试 |
| 编辑器进入失败 | 截图，进入重试 |
| 导出失败 | 截图，进入重试 |
| 下载失败 | 截图，进入重试 |
| 文件归档失败 | 记录错误，进入重试或标记失败 |
| 用户停止 | 保存状态，释放资源 |
| 程序异常退出 | 下次启动根据状态文件恢复 |

所有异常记录：

- 时间。
- 账号。
- 歌词文件。
- 当前状态。
- 页面 URL。
- 错误摘要。
- 截图路径。

## 10. 断点续跑

状态文件按日期、账号和歌词文件名记录处理结果。

- 成功歌曲默认跳过。
- 失败歌曲可重新选择处理。
- 用户可选择忽略历史状态全部重跑。
- 状态文件损坏时自动备份原文件，并从空状态开始。

## 12. 测试计划

### 12.1 单元测试

- 歌名、歌词、风格解析。
- 配置读写和备份。
- 状态文件读写与断点跳过。
- 下载文件归档和重名处理。

### 12.2 步骤级测试

后端提供单步诊断接口：

- 打开创作页。
- 校验专业模式。
- 选择模型。
- 选择虚拟歌手。
- 填入指定歌词。
- 定位生成按钮。
- 定位资产第一首歌。
- 打开编辑器。
- 打开导出弹窗。
- 定位下载菜单。

每一步返回状态、耗时、选择器命中情况和截图。

### 12.3 端到端测试

- 使用 1-2 首测试歌词跑完整闭环。
- 验证日志、截图、状态文件、下载文件和最终归档路径。
- 验证暂停、停止、失败重试和断点续跑。

## 13. 验收标准

1. 本地网页控制台可启动，并显示账号、任务、日志和配置。
2. 可创建多个账号配置，每次选择一个账号运行。
3. 后端能自动启动和关闭对应账号的 Chrome。
4. 能解析歌词并在界面展示解析结果。
5. 能按配置完整执行生成、导出、下载和归档。
6. 每一步都有日志和硬超时。
7. 异常自动保存截图。
8. 用户停止后资源可释放，界面不假死。
9. 中断后重新启动可跳过已完成歌曲。
10. 任务运行中界面持续可操作。
